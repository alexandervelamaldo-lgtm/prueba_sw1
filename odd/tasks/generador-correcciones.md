# Generator corrections

Objective: fix the code-generation defects found in the 2026-10-21 read-only audit (Codex), and add a check that compiles and boots the generated code.
Branch: `yimy` (owner pushes straight to `main`). Delivery: `ask-on-risk`, one commit per task. Test runner: Vitest (`npx vitest run generator shared`); opt-in compile/boot check with `COMPILAR_GENERADO=1`.

## Specs

- **S1** Opt-in check that turns generated code into real evidence: with `COMPILAR_GENERADO=1`, generate the backend for PostgreSQL, MongoDB and Cassandra and compile it with Maven; for PostgreSQL also boot it against a throwaway PostgreSQL (Flyway plus `ddl-auto: validate`) for every inheritance strategy (JOINED, SINGLE_TABLE, TABLE_PER_CLASS) and for UUID and String identifiers; generate the Flutter app and run `dart analyze`. Skipped by default, like `EVALUAR_IA`.
- **S2** Audit item 1 (high): "Cassandra crea sin clave primaria. El mapper construye la entidad sin ID y create() la guarda así, aunque la entidad declara @PrimaryKey". Creating a record must assign an identifier.
- **S3** Audit item 2 (high): "PostgreSQL acepta IDs UUID/String pero emite IDENTITY para ambos. El DDL tampoco les da un valor predeterminado". UUID and String identifiers must be generated by a strategy that works for their type; Long and Integer stay IDENTITY.
- **S4** Audit item 3 (high): "SINGLE_TABLE pierde columnas propias de las subclases … También puede duplicar dtype si el usuario creó ese atributo." The single table holds every column of the hierarchy (subclass columns nullable), and the discriminator never collides with a user column.
- **S5** Audit item 4 (high): "TABLE_PER_CLASS pierde columnas heredadas. Cada tabla se construye con entity.fields, no con los campos de sus ancestros." Each table holds its inherited columns, and the identifier strategy must be one Hibernate accepts for TABLE_PER_CLASS.
- **S6** Audit item 5 (high): "enums válidos pueden generar Java inválido. activo y ACTIVO pasan la validación individual, pero ambos se emiten como ACTIVO." Validation rejects literals that collide once normalized.
- **S7** Audit item 6 (medium): "Flutter interpreta IDs String como int. Solo reconoce UUID como String, y todos los IDs de asociación a-uno son int". Flutter id and foreign-id types follow the real identifier type (String for MongoDB/Cassandra).
- **S8** Audit item 7 (medium): "MongoDB/Cassandra omiten relaciones a-muchos … una N:M no queda representada como colección." Assumption: the owning side of a many-to-many stores the list of target ids (`<name>Ids`), exposed in request and response DTOs; one-to-many stays derivable from the to-one side.
- **S9** Audit item 8 (medium): "unique no queda garantizado en NoSQL. MongoDB no genera índice único; Cassandra usa @Indexed, que no declara unicidad." Assumption: MongoDB gets a unique index (`@Indexed(unique = true)` plus index auto-creation); Cassandra, which has no unique constraint, checks in the service before saving and answers a conflict.
- **S10** Audit item 9 (medium): "las filas iniciales se pierden en MongoDB/Cassandra." Assumption: seed rows are loaded at startup by a generated loader when the collection/table is empty.

- **S11** Found by S1: every Cassandra project fails to compile: `AlmacenIdempotencia.java` imports `org.springframework.data.cassandra.core.cql.WriteResult` ("cannot find symbol").
- **S12** Found by S1: MongoDB `rrhh` fails to compile: `Empleado.java` "method does not override or implement a method from a supertype" (realized-interface methods keep `@Override` after the class is flattened).
- **S13** Found by S1: generated Flutter fails `flutter analyze`: "The await expression can only be used in an async function" in every `*_lista.dart`, and "The argument type 'String' can't be assigned to the parameter type 'bool'" in `producto_formulario.dart`.
- S3, S4 and S5 also cover what S1 found there: a UUID identifier does not compile ("cannot find symbol class UUID" in `ProductoResponse.java`); a String identifier answers 500 on create; SINGLE_TABLE does not boot ("is a subclass in a 'SINGLE_TABLE' hierarchy and may not be annotated '@Table'"); TABLE_PER_CLASS does not boot ("may not specify a '@PrimaryKeyJoinColumn'").

Out of scope (audit, not defects): UML business methods stay skeletons that throw `UnsupportedOperationException`; the Whisper model is still added manually to the Flutter ZIP.
